# keyboard.wtf 1.4.20

This release brings the accepted Jarvis reliability work into one public Windows
app, with Personal API and Managed usage sharing the same local action pipeline.

- Natural selected-text translation uses the current foreground selection,
  retained same-session context, real task progress and verified clipboard
  completion. Screen analysis is not substituted for selected-text requests.
- Screen follow-ups can use the same bounded session screenshot context; explicit
  current-screen requests take a fresh snapshot. Temporary context clears at
  session end.
- Saved website/workflow opens can start the Windows default browser when Chrome
  is closed. Chrome Helper 2.1.28 remains the supported automation integration.
- Live interruption/no-response feedback is truthful and recoverable. Provider
  outages and transcription variance can still occur; lost commands are not
  automatically replayed.
- PersonalOnly ownership stays isolated from Managed credits. Backend release
  preparation strengthens checkout ownership, settlement idempotency and
  subscription-safe account deletion without changing the monthly plan price.
- Settings has clearer first-run/backend information, active hotkeys and update
  notifications. This early release uses the normal installer for manual updates;
  unattended/in-app installation stays disabled pending its remaining safety gates.

The installer is not Authenticode-signed. Windows may show an unknown-publisher or
SmartScreen warning. Use only the official keyboardwtf.com download or official
GitHub Release and verify its published checksum. Chrome Web Store Helper 2.1.28
is already live; do not install a private/developer Helper for ordinary use.

Release publication and paid availability depend on final installed/backend
acceptance; these notes alone do not certify either.
